# 活動總表、週報與訂閱

## 固定活動總表

每日指定時間抓取活動，編輯同一則總表；總表在建立時嘗試置頂。已存訊息 ID，因此重啟不重發總表。只有 Discord 明確回報該訊息已刪除時才重建；權限或網路錯誤會回報失敗。不能置頂時保留已建立訊息，於 `/events_status` 顯示原因。

總表保留設定預看範圍（預設 120 天）內抓得到且符合收錄條件的活動，每頁依訊息長度放至多四場。頁數不限制活動總數。按「全部活動」「比賽」「社群／課程」或上下頁會回覆私人分頁，不會改動公開總表。使用選單選擇活動查看內容。

總表每天刷新資料；來源失敗時保留仍有效的舊活動並標示「來源暫時未確認」。每日成功掃描後，已結束或不再由來源回傳的活動會移出快照。

## 每週週報

`EVENT_WEEKLY_ENABLED=true` 預設啟用。週一作為週起點，於每日掃描時判斷是否有新一期內容。首次啟動或停機恢復後，可在當週補發。只涵蓋未來四週開始的活動，以及報名期限落在四週內的較遠活動。

同一週內容更新時編輯原週報；跨週內容相同時不另發。長清單附上完整 Markdown 文字檔，總表仍可分頁查閱。來源部分失敗時只列當輪確認的項目並標示限制。沒有任何活動時不另發空週報。

## 個人訂閱

1. 在活動頻道開啟總表，從選單選擇活動。
2. 按「訂閱私訊提醒」。每人最多訂閱 20 場。
3. 「我的訂閱」只列出自己的項目；選擇後可取消。私訊內也有取消按鈕。

Bot 在明確報名截止、活動開始前 24 小時內，各私訊提醒一次。檢查週期由 `EVENT_POLL_INTERVAL_MINUTES` 決定，預設 30 分鐘；不是精準到分鐘的鬧鐘。臨近開始才訂閱時，下次檢查若仍未超過時間就會提醒。只有 unknown 的期限不當作報名截止。

來源尚未確認或超過 36 小時未驗證的活動暫停提醒。成員離開伺服器、失去活動頻道權限或封鎖私訊時不改發公開訊息。送信失敗會保存狀態，可在該活動的私人頁面看見。每個時間點的提醒在送出前先記錄派送狀態；如果程序在派送途中中止，送達不確定的提醒不會自動重送，以避免重複私訊。此取捨可能造成單次提醒漏送；不是保證送達的鬧鐘。

## 資料與部署

- PostgreSQL 使用獨立 `bot_event_documents` 表，每個活動頻道一份快照。JSON 模式使用 `data/state.json.events-<channelId>`，位於 git 忽略範圍。
- 快照包含目前活動、兩種公開訊息 ID、最後檢查時間、當期週報摘要指紋及訂閱／提醒狀態。正常掃描會替換資料，活動結束或從快照移除後清除對應訂閱。訂閱不使用新聞的 90 天 TTL。
- 部署維持單一 Bot instance；執行佇列在同一程序內避免定時更新、手動更新、訂閱寫入互相覆蓋，不支援多個副本共同寫入。
- 活動頻道需要發送訊息、讀取訊息歷史、置頂訊息及附加檔案所需權限。無法置頂時仍可手動置頂已建立的總表。
- `/events_now` 更新總表及當週週報，不會繞過週報去重。`/events_status` 顯示總表連結、來源錯誤及本輪提醒數量。
- `MAX_EVENTS_PER_RUN` 已不控制新版流程；完整活動保留在分頁中。三項功能共用 `EVENTS_ENABLED`。
- 公開訊息禁止所有 mentions；總表建立時使用靜音發送。週報每週最多建立一則正常公告（人工刪除後重建例外）。不自動刪除既有公告或舊週報。

目前完成的是程式與模擬測試。推送／部署新版後，才會在 Discord 建立總表、週報及接受成員訂閱；既有 slash command 名稱可沿用，更新描述需要重新執行指令註冊。
